Information Retrieval (efficient searching of Mathlib)
Seems like to be one of the more difficult parts in formal proving since everything in the end is “find the correct Mathlib puzzle pieces”. One of the papers seems to suggest their Search tools doesn’t improve performance a lot so the question is whether it’s really irrelevant or this is the true bottleneck, we haven’t yet found a good Search and should focus on optimising this part - try to test this before thinking about solving Search (maybe by looking at failures?). Also, this feels more like a “how to deal with a huge dataset” problem, probably doesn’t need an agentic approach more like creating a good index/graph.

When people say semantic search what exactly do they mean? Theorems are close to each other if used together in proofs (historically) vs mean the same thing/are about the same topic - can we test which one is better?
What goes wrong in autoformalization (NL → Lean) & is there an easy fix?
The papers I read suggest that often the formalised statement compiles in Lean but has a different meaning (usually is just trivially true). Issues I’ve seen listed are minor things like missing hypotheses, swapping quantifiers or using a wrong lean type (natural numbers treated as integers become 0) etc. This seems very annoying but also I feel like smarter models shouldn’t have an issue with this so I’m quite surprised. Apparently, “collective llm judgement” is also poor.
